# Security Policy

## Reporting A Vulnerability

Do not open a public issue for security-sensitive reports.

Until a dedicated security inbox exists, report vulnerabilities privately to the repository owners or project maintainers through a non-public channel. Include:

- A clear description of the issue.
- Reproduction steps or proof of concept.
- Impact assessment.
- Suggested remediation, if known.

## Response Expectations

- Acknowledge receipt promptly.
- Triage severity and exposure.
- Coordinate remediation before public disclosure.
- Document follow-up actions after the fix is available.

Replace this policy with named contacts and an SLA before the repository is used for production systems.
